Greedy Algorithms

Lecture notes and four interactive exercises.

Opening

What is a greedy algorithm?

A greedy algorithm solves an optimization problem.

  • Optimal substructure: an optimal solution contains in it optimal solutions to subproblems.
  • Greedy strategy: at each decision point, do what looks best "locally". A top-down structure: with each step, reduce the problem to a smaller problem.
  • Greedy choice property: "locally best" = globally best.
First example

Coin change

Problem: give change for n Shekels using the minimum number of coins. Coins: 1, 2, 5 and 10 shekels. Example: n = 38 shekels.

S <- set of all coins
A <- 0              // number of used coins
while n > 0 {
    C <- maximum coin in S
    A <- A + floor(n / C)
    n <- n - floor(n / C) * C
    S <- S - {C}
}

Second example

The fractional knapsack problem

A knapsack can contain a certain weight C of goods. Under this capacity constraint, maximize the total value of the goods you put in.

Example: candy NIS 50 for 10 kilos, chocolate NIS 40 for 5 kilos, ice cream NIS 30 for 5 kilos. If C = 14 kilos, what would you do?

Formally: given G1, G2, ..., Gn, each Gi with weight wi and value vi, let fi (0 ≤ fi ≤ 1) be the fraction of Gi taken. Maximize the total value subject to the total weight not exceeding C. A choice of fractions that respects the capacity is a feasible solution; one of maximum value is an optimal solution.

S <- set of all vi / wi
while C > 0 {
    i <- index of maximum value in S
    S <- S - {vi / wi}
    if (wi < C) {
        take wi kilos of item i
        C <- C - wi
    } else {
        take C kilos of item i
        C <- 0
    }
}

Third example

Activity selection

Problem: given S = {1, 2, ..., n} of n activities, each activity i with start time si and finish time fi (si < fi). Activities i and j are compatible if they do not overlap. Objective: select a maximum-sized set of mutually compatible activities.

Solution: order the activities by increasing finishing time, f1 ≤ f2 ≤ ... ≤ fn.

Greedy-Activity-Selector(s, f)
1. n <- length(s)
2. A <- {1}      // selected activities
3. j <- 1        // last selected
4. for i = 2 to n
5.     if si >= fj
6.         then A <- A ∪ {i}
7.              j <- i
8. return A

Why it works

Optimality of activity selection

Theorem: Greedy-Activity-Selector is optimal.

Loop invariant: before iteration i we hold a feasible solution for activities 1, ..., i-1 with (1) |A| maximal and (2) j minimal for this |A|. The invariant is proven by induction on i; the base case i = 2, |A| = 1, j = 1 is trivial.

Maximality: assume a set Bi with |Bi| > |Ai|. If ai ∉ Bi, then Bi is an optimal solution for {1...i-1}, contradicting (1). Otherwise ai ∈ Bi and ai ∉ Ai; but if greedy did not select ai, it is because ai overlapped the last activity in {1...i-1}, contradicting (2).

Minimal j (earliest finish time): assume a set Bi with |Bi| = |Ai| whose last activity finishes earlier. ai ∈ Bi is impossible (then j would be maximal, contradicting (2)); otherwise Bi is optimal for {1...i-1}, where Ai-1 is already optimal with minimal j - a contradiction.

Knowing the limits

Where greedy fails

Weighted activity selectionSame goal, new constraint

Now each activity also has a weight wi, and we want to maximize the sum of weights. With all weights equal, earliest finish first works. With different weights it may fail: greedy takes three light activities, the best possible count, but if one heavy activity outweighs all three together, the weighted optimum is that activity alone.

A small tree exampleHeaviest path

Task: find the heaviest path from the root to a leaf. Greedy rule: at each node, take the heavier child. Greedy gets 20 → 3 → 1 = 24, while the optimum is 20 → 2 → 10 = 32. Local best is not always global best - we must know when greedy works.

Practice

Four greedy exercises

The refueling scheduling problemSort, then refuel

N cars wait to refuel; car i takes Timei. Choose the refueling order so the total waiting time of all cars is minimal.

Solution: sort by non-decreasing refueling time and refuel in that order, in Θ(n log n). Correctness by exchange: swapping two consecutive cars with times a > b leaves the other cars unchanged and decreases the pair's combined waiting time by a - b, so repeating brings the sorted order without increasing the total.

The polynomial coefficients problemSmall coefficients first

Given an array A of n natural numbers A0..An-1 and X > 1, order the elements so the polynomial A0 + A1X + ... + An-1X^(n-1) is maximal.

Solution: sort the array in ascending order, in Θ(n log n). Greedy choice: in an optimal solution A0 is the lowest value - swapping it with a smaller Amin at index i increases the value, since X > 1. Optimal substructure: the rest of an optimal ordering is optimal for the polynomial starting from X.

Sale at Reuben's kioskPair the expensive ones

A sale gives the cheaper product of every pair for free. After choosing 2n products, pair them so the total paid is minimal.

Solution: sort the prices x1 ≥ x2 ≥ ... ≥ x2n and pair adjacent products, in Θ(n log n). Exchange argument: replacing the pairs of x1 and x2 with (x1, x2) and their partners never costs more, so some optimal pairing contains (x1, x2); remove it and repeat.

Minimum number of open platforms at a train stationTwo sorted lists

Given arrays A of arrival times and D of departure times, find the minimum number of platforms needed so no train waits.

Sort A and D, then walk the day with two indices: when the next arrival is earlier than the next departure, a train enters (curr grows); otherwise a train leaves (curr shrinks). The peak of curr is the answer.

MinPlatforms(A[0..n-1], D[0..n-1]):
    sort(A); sort(D)          // ascending
    i <- 0; j <- 0
    curr <- 0                 // trains at the station now
    ans <- 0                  // max of curr so far
    while i < n and j < n:
        if A[i] < D[j]:       // next arrival first
            curr <- curr + 1
            ans <- max(ans, curr)
            i <- i + 1
        else:                 // train departs, frees a platform
            curr <- curr - 1
            j <- j + 1
    return ans

Example: A = [2.00, 2.10, 3.00, 3.20, 3.50, 5.00], D = [2.30, 3.20, 3.55, 4.00, 4.30, 5.20] after sorting. The peak is 3 platforms.
